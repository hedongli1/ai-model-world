# 交接文档

给下一个接手这个项目的人（无论是人还是 AI）。

读完这份文档你应该能回答三个问题：这个站在做什么、为什么代码长成现在这样、接着该做什么。
其中第二个问题最重要——本项目里有大量**看起来可以简化、实际上简化就会出错**的地方，
下面的「踩过的坑」和「不可违背的原则」两节记录的就是这些，请务必读完再动手。

## 一、这是什么

一个把每个大语言模型拟人化成像素角色的网站。目标用户是**完全不懂大模型的普通人**，
产品目标是「点进来就能一眼看懂当下的大模型格局」。

核心承诺是**发布之后不需要任何人维护**：新模型发布、旧模型退役、价格调整、榜单更新，
全部由 GitHub Actions 每 12 小时自动同步一次，不依赖任何需要续费的 API 密钥。

## 三、快速上手

```bash
npm install
npm run dev          # prebuild 会先合成精灵图（约 13 秒），然后启动开发服务器

npm run sync         # 抓取上游 → data/models.json
npm run sprites      # 由 data/models.json 再生产 public/：精灵图 + 搜索索引（= npm run assets）
npm run search-index # 只重做搜索索引（约 0.5 秒）
npm run bilibili     # 按「{模型名} 测评」搜 B 站 → data/bilibili.json（手动跑，不在同步管线里）
npm run font         # 中文像素字体子集化（改了中文文案后才需要跑）

npx tsx scripts/sync/selftest.ts   # 数据管线的 217 项纯函数自检，不联网
```

两条管线都是**离线确定性**的：不需要任何 API 密钥，同样的输入永远产出同样的字节。

### 日常维护一览（站长视角）

| 多久 | 做什么 | 命令 | 耗时 |
|---|---|---|---|
| 想更新时说一句「更新数据」 | 抓模型 + 补形象 + 重做搜索索引 | `npm run sync && npm run sprites` | 约 90 秒 |
| 发了模型实测视频之后 | 补抓 B 站视频 | `npm run bilibili` | 每个模型 2.5 秒，只抓缺的和 14 天以上的 |
| 改过代码 | 三道闸门 | `npx tsc --noEmit` / `npx eslint src scripts` / `npx tsx scripts/sync/selftest.ts` | 约 10 秒 |
| 发布 | 生产构建 | `NEXT_DIST_DIR=.next-build npm run build` | 约 25 秒 |
| 发 B 站 Toy | 打包 + **必跑**自检 | `npm run toy:build && npm run toy:verify` | 约 100 秒 |

**发 Toy 之前一定要跑 `toy:verify`。** 它把包挂到与线上同构的版本化路径
（`/toy/<slug>/<toyId>-v<版本号>/`，平台真实地址就长这样）下，用真实浏览器把每个控件点一遍。
`toy create` 给的预览链接只能看个大概，它跑在另一个域的 iframe 里，报错在外层看不到。
背景见第六节第 15 条那次「整站没水合却一条报错都没有」的事故。

**只有 `data/` 下的四个文件需要保存**：`models.json`（模型快照）、`bilibili.json`（视频）、
`attribution.json`、`sync-report.json`。`public/sprites/` 与 `public/search-index.json`
是从 `models.json` 现做的，不进版本库。

**建仓之后这张表会缩到一行。** `.github/workflows/sync.yml` 已经写好：定时跑 `sync`、
直推快照、失败自动开 issue。视频那条因为有风控，仍然建议手动或低频定时。

### 用户说「更新数据」时怎么做

在自动同步启用之前，这是唯一的数据更新方式，用户会用一句话触发：

```bash
npm run sync      # 约 15–75 秒。闸门拦截时退出码非零、旧快照原样保留
npm run sprites   # 给新模型补形象 + 重做搜索索引，约 13 秒
```

dev 服务器不用重启（开发态每次请求重读磁盘）。跑完**必须**看这三样，不要只看「写入成功」：

1. 末行「覆盖率速览」里的 **ECI** 不能比上次低太多（上次 37.6%）。看百分比也要看绝对数：
   总量每轮都在涨，新模型天然没有 ECI，百分比小幅下滑是正常的。归零才是 Epoch 又改格式，见踩坑第 11 条。
2. `WARN` 里有没有「表头里找不到分数列」「找不到 X 对应的 CSV」——上游改名的精准信号。
3. 首页截图：「今日格局」八格是否合理、有没有新模型没形象（`npm run sprites` 漏跑）。

然后跟用户汇报：新增了哪些模型、榜首有没有变、有没有异常。本地跑 Hugging Face 一定失败，不用报。

### 体检脚本

`scripts/qa/` 下全部是**只读**脚本，不写盘、不改数据，用来回答「为什么是这个结果」。
这一套是这个项目最有价值的沉淀之一——**每一个都是为了回答一次具体的困惑而写的，
下一次同样的困惑还会再来**。

| 脚本 | 回答什么问题 |
|---|---|
| `why-flagship.ts <厂商 id>` | 这家为什么是这个模型上广场？逐个列出候选与判据 |
| `stale-flagships.ts` | 还有哪些门面不是本家最新的大杯型号？为什么没接班？ |
| `newer-than-flagship.ts` | 屋子下沿的「本家更新」便条会出现在哪几家、覆盖率多少（超 60% 就该收紧） |
| `flagship-rules.ts` | 改动选拔规则会影响多少家？（改规则前必跑，看影响面） |
| `roster-signals.ts` | 广场每位门面各有哪些数据、缺哪些、用了哪些赛制 |
| `bench-names.ts` | models.dev 上游到底有哪些榜单名、各覆盖多少模型 |
| `bench-candidates.ts` | 编程类榜单剔除 AA 之后的剩余量与时效 |
| `bench-detail.ts <榜单名>` | 某个榜单具体覆盖哪些模型、时间跨度多大 |
| `epoch-zip.ts` | Epoch zip 里 80 余个 CSV 各是什么（数量随上游增长）、哪些有 AA/LMArena 血缘 |
| `match-gap.ts` | 上游抓到了却没落到模型身上的成绩有多少 |
| `value-rank.ts` | 性价比排名对不对（验证分位差算法） |
| `flagship-gain.ts` | 接入新数据源能给首屏补多少编程成绩 |
| `shots.ts [baseUrl] [outDir]` | 三个断点批量截图，视觉自验证用 |
| `shot-detail.ts <slug>` | 单个角色详情页整页截图 |

`scripts/toy/verify.ts` 不在这张表里，因为它会写盘（起本地服务）且是发版闸门而非诊断工具，
但性质相同：**它回答的是「页面到底能不能用」，而这件事光看渲染结果看不出来。**
| `verify-text.ts "某段文字"` | **区分「代码没改干净」和「浏览器缓存」**——两者表象一样 |
| `measure-tiers.ts` | 体型档位在精灵图上的实际可辨性 |

> 从中国大陆运行时 Hugging Face 会 TCP reset，参数量与许可证字段会留空并标 `confidence: unknown`，
> 不影响其余部分。生产抓取跑在 GitHub Actions 的境外节点上，不受此影响。

> 本机 3000 端口常被别的项目占用，`next dev` 会自动改用 3001。
> 「改了代码但页面没变」十有八九是**开错端口或浏览器缓存**，
> 先跑 `npx tsx scripts/qa/verify-text.ts "某段文字"` 确认，别急着回去翻代码。
> `loadSnapshot()` 与 `listSpriteSlugs()` **只在生产构建里缓存**，开发时每次请求重读磁盘：
> `npm run sync` / `npm run sprites` 之后刷新页面即可，不用重启。
> 真正需要重启的是 **`npm run build` 之后**：静态导出会把 `.next` 写成导出态，
> 再起 dev 会 404 / 500，先 `rm -rf .next`。子任务并行开发时尤其容易互相踩这一脚。
> 更省事的做法是让构建写到别处：`NEXT_DIST_DIR=.next-build npm run build`
> （`next.config.ts` 读这个环境变量，`.next-*/` 已在 .gitignore），dev 完全不受影响。
> 注意这时**静态导出落在 `.next-build/` 本身，不是 `out/`**：想验收成品就
> `cd .next-build && python3 -m http.server 4321`。仓库里如果还留着一个 `out/`，
> 那是早期默认构建的残骸，别拿它当最新产物。

## 四、不可违背的原则

这些是产品与法律层面的硬约束，改动前必须先确认是不是真的想推翻它们。

### 4.1 数据诚信

**没有数据就说没有数据。** 绝不用 0、`-`、平均值或估算值填补空缺。
这个站的使命是让人看到真实状态，一个假的数字比一句「暂无数据」有害得多。

具体体现：能力条缺数据时画成**带描边的空槽**而不是零长度的条（「没测过」和「得了零分」
必须一眼可辨）；没上榜的模型显示「未参赛」而不是给个假分数；
参数量未公开的角色套雾化斗篷并明确标注；厂商自报的成绩在数字旁缀一个「自报」。

**曾经为了画面好看破坏过这条，后来撤销了**：试过让当家门面在综合智力打平时优先选有编程成绩的模型，
能让广场上有电脑的屋子从 4 家翻到 8 家——但它把 Grok 4.6 换成了 4.5、Qwen3.8 Max 换成了 Preview 版。
拿准确性换观感，撤掉了。相关注释留在 `src/lib/roster.ts`。

**但「没数据就说没数据」不等于「没数据就当它不存在」。** 这是同一条原则的另一面，
在门面选拔上栽过一次：原规则取该厂商 ECI 最高的模型，而 Epoch 的评测有滞后，
厂商刚发的旗舰往往还没有分数——于是「没被测过」被当成了「不够格」，
广场上摆着 GLM-5.2 而 GLM-5.3 已经发布两个月，摆着 GPT-5.5 Pro 而 GPT-5.6 已经上线。
对一个以「一眼看懂当下格局」为使命的站点，这是实打实的误导。
修法见下面第五节末尾的「代际接班」。

### 4.2 合规红线

#### 绝不使用 Artificial Analysis 的任何数据

**这条会被反复质疑**（「AA 是最全的，为什么不用？」），所以把核实过的原文记在这里，
省得下一个人再查一遍。以下引自 2026 年版 *Artificial Analysis Data Platform Terms*：

> **2.5 Anti-Competitive Restrictions.** Customer shall not use the Data to develop, operate,
> or improve any product or service made available to third parties whose primary purpose is
> **benchmarking, ranking, comparison**, competitive intelligence, or model/provider selection
> guidance, without Company's prior written consent.

本站的主要用途就是模型对比与排名，**逐字命中**。几个加重的细节：

- 这条**免费层同样适用**。条款对照表里 Pro 与 Commercial 两栏的 Anti-Competitive Clause
  都是勾选状态，免费 API 更写明 internal use only。
- 靠「只用衍生数据」绕不开。第 1.10 条明确把 *raw Data points republished in any format*
  和 *any output where the underlying Data remains individually identifiable* 排除在衍生数据之外，
  而我们按模型逐个显示分数，正是可个体识别的原始数据。
- 第 2.4(d) 条单独禁止「把 Data 与第三方来源合并成一个对外提供的产品或数据集」，
  那恰好是本项目整条管线在做的事。
- 违反 2.4/2.5 的责任**不封顶**（10.3 条明确不适用责任上限），另有 10.4 条的赔偿义务，
  且第 6 条写明他们会主动监测使用情况。

唯一合法路径是走 Commercial 授权并拿到书面同意，那是项目负责人要去谈的事。

技术上它还会经由 models.dev 与 OpenRouter **第三跳**混进来，且名字完全中性
（`SWE-Bench Pro`、`Terminal-Bench`、`SciCode`），只按名字过滤会全部漏网。
Epoch 的 zip 里 `scicode_external.csv` 有 129 行指向 `artificialanalysis.ai`，
也已拦截。判断逻辑集中在 `scripts/sync/lib/compliance.ts`，
按**名字 + 来源域名双线**判断，写盘前还有一道全树扫描兜底。

**放弃 AA 只损失一个维度：速度与延迟。** 智力、编程、上下文、价格这些，
免费源（Epoch CC-BY 4.0、LiveBench Apache-2.0、models.dev）都能覆盖，
因为 AA 大部分数据本身也是从这些一手源汇总来的。
但托管 API 的吞吐与首字延迟只有它在系统性实测——查过的免费替代
（HexGrid、AgentPerfBench、LLMCheck、Argonne LLM-Inference-Bench）
全是自建 GPU 或 Apple Silicon 上跑开源权重的测试，回答不了「Claude 的 API 多快」。
所以**速度这个维度本站没有，短期也补不上**，只能在详情页外链过去。

#### 绝不抓取 LMArena

其 ToS 明文禁止用自动化手段抓取模型名称与分数。

**但 `benchmarks.webdev_arena_elo` 的上游确实是 LMArena**，这是一个刻意的决定而不是漏洞：
Epoch zip 里的 `webdev_arena_external.csv` 有 121 行 `Source link` 指向
`https://web.lmarena.ai/leaderboard`。我们的合规依据是**消费 Epoch 在 CC-BY 4.0 下的再分发，
而非直接抓取**。`compliance.ts` 里有注释记录这一点，豁免作用域被限死为
「只对 LMArena 家族生效，AA 永不豁免」，并有回归自检。
**下一个人看到它不要当成漏洞误删**——要撤销请先与项目负责人确认。

#### OpenRouter / Vercel Gateway / LiteLLM 只做发现与「事实字段」兜底

不转存原始 JSON，不展示它们的任何自由文本（描述、标签）。允许拿的只有**可独立核实的事实**：
定价、上下文、最大输出、模态——这些是厂商自己公开的数字，聚合器只是转述者。
仲裁是「第一个有值的源胜出」，逐字段记 `provenance`：
定价 models.dev → LiteLLM（多 provider 一致才采信）→ OpenRouter → Vercel；
上下文 / 模态 models.dev → OpenRouter → Vercel → LiteLLM。细节见 `docs/DATA.md`。
OpenRouter 的 ToS 措辞极宽，公开展示 LLM 元数据的站点有被解读为「竞争性服务」的风险，
所以边界划在「事实字段」这一条线上，不再往前。

### 4.3 零 AI 依赖

页面上所有文案由结构化字段套模板生成，**不调用任何 LLM**，也不展示上游返回的自由文本。

两个理由：一是模型信息永远不会被编造（LLM 写模型人设极易幻觉，而这个站的使命恰恰是展示真实状态）；
二是中英双语没有翻译延迟，同一份数据渲染两次即可。

唯一依赖人类常识的地方是 `src/data/vendor-registry.ts` 的厂商形象母题——
机器读得出 DeepSeek 的定价，读不出它应该是一头鲸鱼。这做成了一张**查表而非逻辑**：
未收录厂商自动落到 `wanderer`（兜帽旅人），加不加系统都能跑。

### 4.4 跨赛制分数永不混算

**这是全站最容易被无意破坏的一条。** 编程能力被切成了 31 个互不兼容的赛制，
`ModelRecord.coding` 是一个 `BenchmarkScore[]`，一个赛制一条，绝不合并成单一分数。

数量级的差距有多大：SWE-bench Verified 中位数 75.7，
而难度更高的 SWE-Bench Pro 被 Scale 官方测出来只有 41.0——**同一个模型换套评测脚手架
就能差二三十分**。同一列 Pro 里，Scale 官方榜的中位数 41.0 与厂商系统卡自评的 59.0
又差 18 分，因为两边的 agent 脚手架根本不是一套。

三条硬性做法：

1. **分位池按「赛制 + 测量方」分组**（`src/lib/aptitude.ts` 的 `poolKey`）。
   只按赛制分还不够——Epoch 复跑的 25 个模型和厂商自报的那批不是同一个分布。
2. **量纲不可混。** `BenchmarkScore.unit` 有三种：`pct`（百分数）、`elo`、`index`。
   ALE-Bench 的成绩是 137–2177 的自定义标度、AlgoTune 是 1.3–2 倍的加速比，
   **都不是百分数**。渲染一律走 `src/lib/format.ts` 的 `formatScoreByUnit`，
   曾经漏掉 `index` 分支，ALE-Bench 的 2176.9 被印成了「2176.9%」。
3. **广场卡片上不显示原始分数，也不显示名次，只显示分位档。**
   原始分数不可比（见上）；名次也不可比，因为分位池大小从 6 到 85 不等，
   「6 个里第 2」和「25 个里第 2」显示出来都是「榜内#2」。
   **分位档是唯一跨池可比的表达。** 原始分数、赛制、测量方、精确名次全部
   留在悬停提示与详情页的「编程战绩（按赛制分列）」。

排行榜与「编程第一」这类断言只在 Verified 量纲内做。

赛制的中文名、口径说明、展示优先级在 `src/data/coding-leagues.ts`——
这是继厂商注册表之后**第二处人类常识层**，同样是查表而非逻辑，
未收录的赛制自动落到通用兜底文案，不会让页面崩掉。

### 4.5 排版规则

**像素字体只用于站名与纯拉丁/数字**（模型名、名次、门楣日期）。
**所有中文一律用系统无衬线体，最小 12px。**

中文像素字在 12px 以下笔画会粘连，读一两个词行、读一段话很费劲。
游戏感应该来自像素画、硬边框面板、配色和动画，不该靠让字变难认。

## 五、贯穿全站的一个模式：自校准分位

**凡是把连续量映射成档位的地方，一律用「当前全体模型的分位数」，不用写死的阈值。**

已经这样做的有八处：

| 位置 | 自校准的量 |
|---|---|
| `buildSizeScale` | 体型档位 |
| `buildPriceScale` | 价格档位 |
| `buildComputerScale` | 房间里的电脑档位 |
| `buildAptitudeScale` | 四条能力横条的填充比例 |
| `buildValueScore` | 性价比（智力分位 − 价格分位） |
| `assignTraits` | 标签稀有度裁剪（35%） |
| `buildVisualPruning` | **视觉元素**稀有度裁剪（60%） |
| `eciTieThreshold` | 门面接班的「分数打平」阈值（ECI 相邻差的 90 分位） |

两个理由：

**其一，写死阈值会让档位失效。** 同一时刻的旗舰模型定价高度聚集，
绝对阈值会把它们全部塞进同一档，广场上所有大厂角色一样高、穿一样的衣服。

**其二，写死阈值会随时间悄悄烂掉。** token 价格逐年下降、上下文窗口普遍变大，
若干年后全世界的模型都会掉进最低档——而这正是一个「发布后没人维护」的站点最危险的失效方式，
因为它不会报错，只会慢慢变得毫无意义。

代价是档位表达的是「在当前这批模型里算大/贵/强」而非绝对值。对一个展示「当下格局」的站点来说，
这个相对语义反而更贴近用户想问的问题。**绝对数值始终在角色房间的属性面板里如实显示。**

### 5.1 代际接班：自校准思路的第五处应用

广场上每家只站一个「当家门面」，原规则是取该厂商 ECI 最高的模型。
这条规则有一个系统性偏差：**Epoch 的评测有滞后，新旗舰往往还没有分数**，
于是它们根本不参与选拔。实测后果是 GLM-5.3 发布两个月后广场上仍站着 GLM-5.2。

现在的规则是：先选出 ECI 冠军，再看有没有被自家更新的型号接班。接班要满足二者之一：

- **分数打平且更新**。「打平」的阈值是**全体模型 ECI 相邻名次差的 90 分位数**
  （当前 0.82）——比九成的相邻名次差还小的差距，不足以支撑一个二元判断。
  这个阈值自校准：上榜模型变多时相邻差整体变小，阈值自动收紧。
- **还没有分数，但价格档不低于在位者**。价格档是厂商自己对产品定位的声明。
  同档或更高价、且晚了至少 7 天发布，是「这是新一代主力」的强信号；
  反过来更便宜的新型号（GLM-5.3-Flash、Qwen3.8 27B、Nemotron Lightning）
  是同代小杯，不构成接班。

实测这条规则在 42 家厂商里只改变 2 家（openai、zhipuai），正是出问题的那两家，
其余全部不变——**改动足够外科手术，说明规则抓的是真问题而不是在乱动**。

两个刻意不做的选择：

1. **不解析型号里的版本号。**「GPT-5.6 > GPT-5.5」看着好判断，
   但 `Muse Glimmer 30B`、`Claude Fable 5` 这类命名没有可靠的版本位，
   一条在多数厂商上失灵的启发式比没有规则更糟。
2. **不用「最近 N 天」的固定窗口圈当代。** 试过 45/60/90 天，都会误伤：
   60 天窗口把 NVIDIA 有分数的 Nemotron 3 Ultra 挤出当代，
   换上了没分数的小杯 Nemotron 3.5 Lightning。窗口太短丢旗舰，太长修不了 GPT。

配套还改了一处排序：**大陆内的厂商位次按「该厂商全部存活模型的最高 ECI」排**，
不按门面自己的分。否则门面换成尚未被测的新型号之后，
智谱会因为 GLM-5.3 暂无分数被甩到大陆末尾，和毫无数据的长尾厂商排在一起。

体检脚本：`npx tsx scripts/qa/why-flagship.ts <厂商 id>` 看单家的选拔过程，
`npx tsx scripts/qa/flagship-rules.ts` 看规则改动在全部厂商上的影响面。

## 六、踩过的坑

按「不知道就一定会再踩一次」排序。

### 数据侧

1. **OpenRouter 的 `created` 不是发布日期，是上架日期。** 实测最大偏差 179 天，
   而且偏差**系统性地集中在中国厂商与开源模型**上——直接用它会把字节的 Seed 2.0 Code
   在时间轴上后移半年。发布日期取多源最小值 + 60 天异常护栏，锚点是 models.dev 与 Epoch。

2. **models.dev 与 OpenRouter 不是独立源。** 前者的 CI 每小时从后者抓取，
   把它们当作「互为兜底」是无效的。真正独立的交叉校验源是 Vercel AI Gateway 与 LiteLLM。

3. **AA 数据会第三跳混入且名字中性**（见 4.2）。

4. **`swe_bench_pro` 内部混着两套互不兼容的测法**（见 4.4）。

5. **`undefined !== null` 为真。** 覆盖率探针原本用 `!== null`，
   而历史快照里没有新字段时读到的是 `undefined`，于是「字段不存在」被算成 100% 覆盖率，
   新字段上线第一次运行必定触发一条假告警。**以后每加一个字段都会踩这个坑。**

6. **`limit.context = 0` 表示「不适用」而不是真的 0。** 能通过「非空」检查却是假值。

7. **models.dev 的 `license` 字段里混进过模型 id**（值是 `"qwen3.8-max"`）。
   归一时用启发式识别并归到 `null`，不要造一个假的 SPDX。

8. **各源分隔符习惯不同会凭空造出重复角色**：`seed-1-6-flash` vs `seed-1.6-flash`、
   `qwen3-14b` vs `qwen-3-14b`。不做 alnum 归一会多出十几个幽灵重复模型。

9. **退役判定会架空「模型总数不得减少 10%」这道闸门。** 退役模型要留在快照里当幽灵，
   总数就永远不降。必须比较**存活模型数**而不是总数。

10. **发布日期有三种精度。** models.dev 有若干条只有 `YYYY-MM`。
    严格 ISO 解析器会静默出错，必须用宽松解析并把精度存进 `releaseDatePrecision`。

10b. **服务档位别名会冒充新一代旗舰，而且在两层都会冒充。**
    `gpt-5-fast`、`o3-mini-high`、`kimi-k3-fast` 是同一模型的计费/推理档，不是新型号。
    管线侧第一版快速晋升放进 62 个「新模型」，一半是这种别名；前端侧 Kimi K3 Fast
    比 Kimi K3 晚 11 天、贵 50%、没分数，完美满足「新一代主力」的接班条件，广场门面
    变成了一个计费档。两处现在共用同一张后缀表（`SERVICE_TIER_SUFFIXES`），
    剥后缀后撞上已有 id 的一律不算新模型。刻意不收 `-medium`、`-pro`，那是真型号。
    **改这张表时两边要同步改。**

11. **上游会悄悄挪文件、改列名，而闸门当时没拦住（2026-09-05 事故）。**
    Epoch 把 ECI 从根目录 `epoch_capabilities_index.csv` 挪进
    `epoch_capabilities_index/eci_scores.csv`，列名 `ECI Score` → `eci`，**并且去掉了 API 型号列**，
    只剩展示名（"Gemini 3.1 Pro"）。三重后果：
    - 解析器按旧文件名找不到 → ECI 覆盖率 38% → 0%，而闸门只盯 id/name/上下文的绝对跌幅，**放行了**。
      现在 `SANITY.loadBearingKeys`（ECI、任一编程成绩）按**相对跌幅**拦截，跌过一半就拒绝写入。
    - 修好文件名后只接回 159 个：其他 CSV 仍按型号登记（`gemini31propreview`），ECI 登记在展示名
      （`gemini31pro`）上，`lookupEpoch` 「严格键一命中就返回」导致 ECI 被同一模型的另一个别名键遮住。
      现在从严到宽逐档**只补缺失指标、不覆盖**，与 `lookupEpochCoding` 同一条纪律。接回 207 个，比事故前还多。
    - `slugVariants` 的后缀剥离只认连字符，"Grok 4.3 Beta" 剥不出 `grok43`。现在先把空格/下划线统一成连字符。
    教训：**凡是前端排名依赖的字段，都必须有相对跌幅闸门**；单看绝对百分点对覆盖率本就不高的字段形同虚设。

12. **合规拦截发生在解析阶段，而 HTTP 缓存早于解析（2026-09-17 事故）。**
    仓库公开后第一次跑 sync workflow，`git add data/` 把 `data/.cache/` 的 165 个文件
    （16 MB）一并提交进了公开仓库。其中 `openrouter.ai/api/v1/models` 那一条的
    响应体含 **187 处 `benchmarks.artificial_analysis`**——管线在解析时会剔除该字段，
    但缓存存的是剔除之前的原始响应，于是整套合规拦截被绕过去了。
    两个放大因素：`.gitignore` 只写了 `/data/raw/`，没想到还有第二个原始响应落盘点；
    缓存体是 **base64** 存的，明文 grep 查不出来，第一次扫描误报「干净」。
    现在三道防线：`.gitignore` 加 `/data/.cache/`；workflow 用显式 pathspec
    `git add -A -- ':(glob)data/*.json'`；提交前校验暂存区，出现顶层 JSON 以外的文件即失败。
    教训：**「我们不展示 X」不等于「仓库里没有 X」**。任何把上游响应落盘的地方
    （缓存、日志、artifact、调试转储）都是一个独立的再分发面，加一个落盘点就要重做一次合规评估。

13. **Epoch 用括号区分同名升级版，去括号后会撞掉真身（2026-09-17 发现）。**
    上游同时有 `DeepSeek-R1 (May 2025)`（141.29，其实是 R1-0528）和 `DeepSeek-R1`（138.97，初版）。
    `epoch.ts` 原来把 `stripParenthetical(name)` 的结果也注册进**严格键**，
    于是括号行占住了纯名行的键位，后写覆盖先写——DeepSeek-R1 拿到了 R1-0528 的分，
    DeepSeek-V3 拿到了 V3-0324 的分，两个老型号排名凭空虚高约 3 分。
    上游 43 条带括号的行里只有 3 条存在同名纯名行，另外 40 条**必须**靠这次剥离才能匹配，
    所以修法不是删掉它。
    **第一版修法只降级到宽松层，结果错误只是换了个地方**：轮到 `deepseek-r1-0528` 去查时，
    它的严格键 `deepseekr10528` 没人占，退到宽松层照样跟初版抢 `deepseekr1`，
    于是升级版反过来拿了初版的分，错误总数一个没少。**只验「我改的那个对了吗」会漏掉这种搬家式的回归，
    要把配对的另一半一起验。**
    最终修法两步走：去括号名降级到宽松层（兜住那 40 条），同时用 `date` 列补一个
    `名字 + MMDD` 的严格键——上游给的是精确日期（"(May 2025)" → 2025-05-28），
    正好拼出 `deepseek-r1-0528` 的形状，让升级版精确命中自己那行。
    编程成绩那条路径 `registerLeagueScore` 一直把去括号名只放宽松层，这次是让 ECI 路径跟它对齐。
    教训：**同一份数据的两条索引路径写法不一致时，先怀疑不一致本身**——
    正确的那条就在隔壁，二十行之外。发现方式是拿 `data/models.json` 跟上游 zip 做逐值比对，
    这类核对不能只看「覆盖率有没有掉」，要看**值本身对不对**。

14. **`trailingSlash: true` 遇到末段含点就不补斜杠，近四成详情页在严格静态托管上 404（2026-09-17 发现）。**
    Next 把 `qwen-2.5-72b` 这种末段当成文件名，于是链接输出 `/model/alibaba-qwen-2.5-72b-instruct`
    （无斜杠），而导出的文件在 `.../index.html`（是个目录）。本地 `python3 -m http.server`
    和 Vercel 都会做 `/x` → `/x/` 重定向，所以本地怎么点都是对的；换成不做重定向的对象存储
    （B 站 Toy、部分 CDN 静态托管）就是实打实的 404。全站 556 个模型里 215 个（39%）slug 带点。
    修法是 `toSlug` 把点转成连字符（转换后逐个核对，零碰撞），并加了两条自检锁住。
    教训：**「本地点得通」不等于「哪都点得通」**，静态站的路由行为一半由托管方决定；
    验证要用最笨的文件服务器，而且要对着**导出的文件名**核链接，别只看浏览器点得开。

15. **相对路径改错了地方，整站水合静默失败（2026-09-17 事故）。**
    现象是**页面看着完全正常，所有按钮点了都没反应，控制台一条报错都没有**。
    不是排行榜坏了，是首页、时间线、厂商页、详情页全都没水合，整站退化成一张截图。
    线上跑了半天，Toy 随后被下架。
    起因是 `pack.ts` 为了适配不固定的挂载路径，把产物里的 `/toy/ai-model-world/`
    按**每个文件自身的深度**换成了 `../`。这对 HTML 成立，对 JS 不成立：
    JS 里的相对路径是相对**文档**解析的，而 chunk 躺在 `_next/static/chunks/`（深度 3），
    按它自身深度算出的 `../../../` 从页面文档解析会直接飞出站点根。
    更隐蔽的是第二层：**光把 HTML 的 `<script src>` 改成相对路径也会挂**，哪怕解析后
    完全正确。turbopack 的加载器用 `document.querySelectorAll('script[src="…"]')` 去重，
    比的是 **src 属性的字面值**，要找的字符串是 `TURBOPACK_CHUNK_BASE_PATH + chunk 路径`。
    对不上它就重插一遍脚本，并且等在一个永远不会 resolve 的 promise 上，安静地卡死。
    正确解法是让这三者用**同一个字符串**：前缀一律剥成相对包根（`_next/static/x.js`）、
    每个 HTML 注入按深度算好的 `<base href>` 负责解析、运行时把
    `TURBOPACK_CHUNK_BASE_PATH` 设成 `_next/`。CSS 是例外，它的 `url()` 相对样式表自身
    解析，仍按文件深度处理。
    **挂载路径确实是变的，别想着写死**：线上真实地址是
    `/toy/<slug>/<toyId>-v<版本号>/`，版本号平台生成、每次更新都变，
    外面在 bilibili.com 用 iframe 套着。所以自检必须挂在带版本号的路径下，
    拿 `/toy/<slug>/` 验会放过一整类问题。
    顺带挖出第二个坑：`.txt` 预取负载删掉之后客户端路由会退化成整页跳转，
    而跳转目标是 `/model/x/` 这种目录 URL，在只认完整文件路径的对象存储上就是 404。
    修法是注入一段捕获阶段的跳转兜底，自己把 URL 算对再跳，绕开路由；
    全局搜索原先用 `router.push`，拦不到点击，一并改成了真链接。
    教训：**「页面渲染正常」跟「页面能用」是两回事**，而且水合失败不报错。
    自检必须是端到端的「点一下看状态变没变」，这就是 `npm run toy:verify` 存在的理由，
    它会把每个赛道按钮、每个筛选控件、每条站内跳转、搜索都真点一遍。发版前必跑。

### 视觉侧

11. **加权平均会向中位数回归、压缩值域。** 体型档位第一版用「价格档 × 命名档」的加权平均，
    结果所有旗舰模型全部落在第 4 档。改成「先算连续分数、再对全体做五等分」才拉开。

12. **LPC 的身体类型不按身高排序。** `female` 比 `teen` 矮，实测档位 2→3 是 **-1.5px**，
    更大的模型反而更矮。精灵图自身撑不起 5 档身高（可用身体轮廓只有三种），
    档位由前端的 `TIER_SCALE` 显示缩放接管。体检脚本 `npm run qa:tiers`。

13. **规则重复的点阵在像素画里会读成图案，不会读成雾。** 雾化斗篷第一版用等间距点阵模拟半透明，
    在页面上读起来像下划线或标尺刻度。改成按像素坐标哈希的不规则抖动才对。

14. **满屏同一块标签等于没有标签。** 「百万记性」在旗舰模型里几乎人手一块。
    `assignTraits` 会剪掉出现率超过 35% 的标签，只有「全球第一」「已退役」这类天然稀有的永远保留。

15. **叠加层的位置不能硬编码百分比。** 头顶高度随体型、发型体积、有没有戴耳机而变，
    实测两个角色的颅骨顶相差 3 像素。用 manifest 里合成时实测的 `anchors`。

16. **Zpix 像素字体不是开源字体。** 3000+ stars 让很多人误以为是，实际单个商业产品授权 ¥7000，
    且版权声明明文禁止「拆分」——网页子集化恰恰就是拆分。用 Fusion Pixel Font（OFL-1.1）。

17. **`aria-pressed` 不能用在链接上。** 那是给切换按钮的，会让读屏软件把导航念成一排开关。
    当前页只用 `aria-current="page"`。

18. **「上游有数据」和「数据被用上了」是两回事。** `scripts/sync/sources/epoch.ts`
    每次同步都下载 Epoch 的 zip（77 个 CSV），但 `filePatterns` 只挑走 6 个——
    **12 个编程榜单在本地躺了几个月没人解析**，接上之后覆盖率直接翻倍。
    加数据源之前先跑 `epoch-zip.ts` 看看已经下载的东西里还有什么。

19. **合规审计必须先扫全量再决定解析谁。** 反过来做（只审计准备解析的文件）
    会让被跳过的文件永远查不到，报告写「拦截 0 个」看似干净其实根本没查。

20. **不是所有分数都是百分数。** ALE-Bench 是 137–2177 的评分标度、
    AlgoTune 是 1.3–2 倍的加速比。渲染时「非 Elo 即百分数」的二分法会印出「2176.9%」——
    一个看起来像数据错误、实则是渲染错误的数字，比缺数据更伤可信度。

21. **同一个榜单跨题目集换代之后不可比。** LiveBench 在 2025-04-02↔04-25 换过题库，
    同一模型的 Coding 分中位差 27.6 分、最大 41.9。判断断点要看 task 列名而不是日期。

22. **「取最高分」在迭代快的领域会系统性偏向旧模型。** 见 4.1 末尾与 5.1。

23. **用合成指数的小数点后一位做二元裁决，会掩盖逐项对比里的真相。**
    Claude Fable 5 与 Opus 5 的 ECI 差 0.9，但逐项看是 2:2，
    而 Opus 赢的科学一项领先 8 分、输的两项加起来才 2 分。
    能逐项对比就别只看合成分。

24. **`Number('')` 是 `0` 且 `isFinite` 为真。** 空白列会被当成 0 分算进均值，
    直接把分数砍半。解析上游 CSV 时必须先判空再转数字。

25. **改选拔规则前先跑影响面。** `flagship-rules.ts` 会列出全部 42 家的新旧对比。
    试过的两条错误规则都是靠它挡下来的：「取最新」把谷歌的 Gemini 3.7 Flash
    误判成小杯过滤掉了（名字带 Flash，可那恰恰是谷歌当代最强的），
    还让六家厂商直接空了；「最近 N 天算当代」在 60 天窗口下
    把 NVIDIA 有分数的 Nemotron 3 Ultra 挤出去，换上了没分数的小杯 Lightning。
    **一条规则在两三家上看着对，不等于它在四十家上是对的。**

### B 站视频（为「B 站 Toy」准备的一块）

| 文件 | 职责 |
|---|---|
| `scripts/bilibili/refresh.ts` | `npm run bilibili`，按「{模型名} 测评」搜 B 站，写 `data/bilibili.json`（已提交，约 250 KB） |
| `src/lib/videos.ts` | 筛选与排序规则（`pickVideos`），脚本和页面共用同一份 |
| `src/components/character/VideoList.tsx` | 详情页底部的卡片列表，最多 12 条 |
| `src/components/character/BiliLink.tsx` | Toy 容器内走 `toy.navigate` 原生打开，容器外退回 `<a target="_blank">` |

六件必须知道的事：

1. **只能离线抓，不能现搜。** B 站接口没给任意站点开 CORS，而这个站是纯静态导出、没有服务端可代理。
   也别挪到构建期：一轮 200+ 请求，等于把「能不能发版」押在别人的风控策略上。
2. **手动跑，不在 `npm run sync` 里。** `npm run bilibili` 补缺和过期的（14 天），
   `npm run bilibili -- --force` 全部重抓。**每抓完一个模型就落盘**，被风控掐断时保留进度，
   过一阵再跑一次接着抓。
3. **覆盖范围：在役 且（综合智力前 120 或 180 天内发布）= 231 个模型**，实测 137 个搜得到视频、共 818 条（其中 34 个满 12 条）。全量重抓约 32 分钟。
   第一版定的是「前 60 / 120 天」，结果 DeepSeek V4 Pro（ECI 排 61、发布 146 天）两条线各差一点
   被漏在外面——那是个有 41 万播放实测视频的热门模型。**门槛卡在「刚好漏掉知名模型」的位置就是定错了**。
4. **搜索结果不能直接用。** 搜「DeepSeek V4 Pro 测评」前几条里混着「DeepSeek 开发指南」
   「深夜宕机，天才程序员的陨落」。过的是和站内其它地方同源的严格规则：
   **标题里必须出现这个模型的名字**（折叠比对 + 词边界，防止 `grok4` 撞上 `grok4.6`）。
   规则写在 `src/lib/videos.ts` 而不是脚本里，改规则不用重新联网抓一遍。
   放宽过一次到「系列词干」，立刻把「Claude Code 封号」挂到 Claude Fable 5 上——**宁可漏不可错**。

   唯一的例外是**日期型号**：`DeepSeek V4 Flash 0731`、`Qwen3 235B A22b 2507` 这种后缀
   是厂商给 API 快照编的号，绝大多数视频不会写。这类模型**两个名字都搜、结果合并、
   两个名字都拿去匹配**，并把不带日期的那个记进 `matchedName`，页面标题上如实显示。
   注意不能只搜短名：词边界规则下 `deepseekv4flash` 后面紧跟 `0731` 不算一个完整的词，
   真写了 0731 的那条反而会被滤掉。也不能「零条才退化」——0731 那页曾经只剩 1 条，
   刚好非零，于是整条产品线的实测全没进来。

   另外**一定要翻页**。一页 20 条，过完标题闸门大约只剩四分之一：
   「DeepSeek V4 Flash 测评」第 1 页过滤后 4 条、第 2 页累计 7 条、第 3 页累计 9 条。
   现在最多翻 3 页、**凑够 12 条就停**，所以热门模型多半一页就够。
   只翻一页的那一版被用户当场抓到：「B 站搜明明能搜到更多」。
5. **排序：站长的视频置顶，其余按播放量降序。** 不沿用 B 站的相关性顺序，因为那个顺序说不清；
   播放量是卡片上就印着的数字，读者能自己判断排序合不合理。卡片上**必须显示 UP 主名字**——
   这些是站外用户的作品，不是本站的评测结论。
6. **封面 `<img>` 必须带 `referrerPolicy="no-referrer"`**。hdslb 有防盗链：带非 bilibili 的
   Referer 去取会 403，浏览器接着报 `ERR_BLOCKED_BY_ORB`，整块图白掉。不带 Referer 反而正常。

接口现状（2026-09 实测）：搜索 `x/web-interface/search/type` 可用，**要先访问一次 bilibili.com
换 `buvid3` cookie**，间隔 2.5 秒跑 143 个请求没被掐。空间接口 `x/space/arc/search` 已经基本
一翻就 `-412 request was banned`，别再指望它。Toy 开放能力里的 `getAuthorVideos`
只能查**当前 Toy 作者本人**的稿件，没有任意搜索。

| 文件 | 职责 |

三件必须知道的事：

1. **索引是再生产物**，跟精灵图一样不进版本库。`npm run sprites`（= `npm run assets`）
   会把精灵图和索引一起重做，所以「更新数据」的两条命令不用改。单独重做用 `npm run search-index`。
2. **索引按需加载**。导航条在 580 个静态页面上都有，内联索引等于给每次访问都加 9 KB。
   现在是聚焦或鼠标移上搜索框才 fetch，模块作用域缓存，整站只拉一次。
3. **`search.ts` 的 `matchesConcept` 必须和 `filters.ts` 的 `makePredicate` 同义**。
   搜索结果上写着「5 个」，点进去总表必须也是 5 个——这两处对「多模态」「开源」「国内」
   的判定一旦漂移，就是在页面上自相矛盾。改了任意一边都要对照另一边。
4. **防抖 140ms + 输入法合成态屏蔽**。挡的不是算力（553 个模型匹配不到一毫秒），
   是中间态：拼音输入法每敲一个字母都会触发 `input`，不挡的话结果面板会在
   「z / zh / zhi / zhip…」之间疯狂重排。`compositionstart/end` 期间完全不查，
   只有落字之后才走防抖。防抖未到点时显示「搜索中…」，**不要显示「没有匹配」**。

概念词表（`CONCEPTS`）覆盖三个维度：类型（多模态 / 视觉 / 全模态 / 图像生成 / 视频生成 / 语音 / 文本）、
开放（开源 / 闭源）、地区（国内 / 国外）。**每个维度最多取一个，可以叠加，还能再叠一个厂商**——
「智谱 多模态」会算出 `?vendor=zhipuai&kind=multimodal` 加一个实时数量。
另有四个赛道快捷入口（上下文最长 / 最便宜 / 最划算 / 最新发布）直通排行榜，它们不参与组合。
想加新概念就往 `CONCEPTS` 里加一行；**前提是它能落成一个已有的筛选参数**，
否则就是一个点了没结果的词，比不加更糟。

### 管线

`scripts/sync/` 数据同步，`scripts/sprites/` 精灵图合成，两者互不依赖。
`scripts/sync/selftest.ts` 有 217 项纯函数自检，改动仲裁逻辑后务必跑一遍。

管线侧几个新约定（详见 `docs/DATA.md`）：

- **榜单 id 按 Epoch 文件名，不按 metadata 的 `benchmark` 列**——"Terminal Bench" slug 化会撞上
  models.dev 侧无版本的 `terminal_bench`（另一个人群）。上游展示名放在 `sync-report.json` 的 `upstreamName`。
- **手写规格优先于 metadata 声明的列**。METR 声明 `average_score`（0–1 归一分）但有意义的是
  `Time horizon`（分钟）；GSO、Fiction.Live 也各有既定口径。metadata 只补元信息。
- **快速晋升有服务档位守卫**：剥掉 `-fast/-free/-flex/-priority/-batch/-xhigh/-high/-low`
  后撞上已有模型的不走快速晋升。第一版没这条守卫时 62 个「新模型」里一半是 `gpt-5-fast`、
  `o4-mini-high` 这类别名。刻意不收 `-medium`、`-pro`，那是真型号。
- **未接入的 Epoch 榜写进 `epochFilesSkipped`**：`btf3`（Brier，越低越好，契约没有方向字段）、
  `forecastbench`（量纲判不出）、`gdp_pdf`（列名不在启发式表）、`live_bench_external`（旧题集）。
  要接 `btf3` 得先给 `BenchmarkMeta` 加 `higherIsBetter`。
- Terminal-Bench 2.0 榜上 DeepSeek 有 8 个同分 39.6% 的条目（Chat / V3 / V3 0324 / V3.1 …），
  疑似上游按别名把同一分数挂到了多个型号上，**尚未核对**。

## 八、精灵图的身份/状态分层

这是一个容易被误改回去的架构决策，单独说明。

**精灵图只烘焙「这个模型是什么」**：身体、发型、五官、服饰、鞋、眼镜/眼罩、耳机、
画笔调色板、钥匙、工具腰带。这些只有模型本身变了才会变。

**状态层由前端 DOM 现画**：皇冠（排名每天在变）、思考光环、新生闪光（30 天必然过期）、
雾化斗篷、幽灵态。

好处是排名一变、下次构建当场摘冠，**不需要重新合成任何一张 PNG**；
而且 DOM 层不受 64 像素画布限制，皇冠能画得比烘焙时清楚得多。
代价是前端要知道「头在哪」，靠 manifest 的 `anchors` 解决。

`manifest.json` 顶层的 `overlaysBaked: false` 是两条管线之间的握手信号。
**前端读它而不是写死**——万一哪天合成器改回烘焙，前端不至于画出双份皇冠。
读不到清单时保守地认为已烘焙，宁可少画也不要画重。

## 九、已知缺口

诚实列出做不到的部分，接手时不要以为是 bug。

**编程覆盖 45% 左右，而且已经到顶了。** 这个数字从 17.9% 一路做上来（models.dev 全部编程榜
→ Epoch zip 里 12 个没被解析的 CSV → LiveBench 官方源），但**再往上没有多少空间**：
广场 39 位门面里 16 位有成绩，剩下 23 位在任何合规第三方评测里都查不到，
字节的 Seed 系列在 13 个 Epoch 编程 CSV 里一条都没有。
关键判断是**现在已经没有「有智力分却没编程分」的门面了**——
瓶颈从数据源转移到了「这些厂商压根没被人测过」。
剩下的候选源（SWE-rebench、SWE-bench 官方、SWE-bench-Live、EvalPlus）
边际增量只有 +5/+1/+1/+2，且各有许可证问题，详见
[coding-benchmarks-2026.md](./research/coding-benchmarks-2026.md) 第 1 节。

**视觉理解只有布尔值。** MMMU 没有官方机器可读源、Epoch 未收录、AA 不可用，
所以只能表达「支持/不支持图像输入」，做不出强弱梯度。

**闭源旗舰的参数量与训练算力基本拿不到。** 训练算力已从 Epoch 接入（81/520），
但闭源旗舰只有 10/94——Epoch 对 GPT-5 / Grok 4 之后的闭源模型基本没有估算。
「参数量拿不到就用 FLOP 代替」这条常见思路对最需要它的那批模型恰恰不成立。

**某些厂商的「门面」是数据说了算，不一定是常识里的旗舰。** 例如腾讯当前门面是翻译模型
HY MT2 Plus——因为腾讯没有任何模型有第三方成绩，规则只能退到「最新 + 价格档」。
这是「零人工干预」的代价，不是 bug；要改只能在注册表里加人工标注，目前刻意没加。

**长文本实测覆盖率 2.1%。** 只能等 Epoch 更新 fictionlivebench，数据侧没有别的路。

**速度维度不存在，而且核实过确实补不上。** 只有 Artificial Analysis 系统性实测托管 API
的吞吐与首字延迟，而它禁止再分发（见 4.2）。查过的免费替代
（HexGrid open-llm-benchmarks、AgentPerfBench、LLMCheck、Argonne LLM-Inference-Bench）
全部是自建 GPU 或 Apple Silicon 上跑开源权重的测试，回答不了「Claude 的 API 多快」。
llm-speed.com 声称覆盖托管 API 但是 2026-07 才发布的新项目，做零维护数据源太冒险。
可行的折中是详情页放一条外链——超链接不复制任何数据，完全合规。

**广场上「每家一间屋」与「全球榜首」是两回事。** 屋里站的是每家当下的门面（可能刚发布、还没分），
「今日格局」里站的是有第三方成绩的冠军。两者会短暂不一致：Fable 5.1 发布后两周内，屋里是 5.1、
「最聪明」还是 Fable 5。读者确实问过「为什么最聪明的不是 5.1」。试过在横条标题旁加一行
「刚发布、等待第三方评测：…」，用户判为废话、要求删掉——**首屏只放结论，解释放在悬停提示和详情页。**
新旗舰拿到 ECI 的典型延迟是 1–2 周（GPT-6 Astra 9 月 3 日发布、9 月 5 日已有分，Fable 5.1 花了 5 天）。

**单榜取最大值会偏向老模型——已经翻过一次车。** 「最会编程」曾直接取 Epoch 复跑
SWE-bench Verified 的最高分。那张榜只有 25 个模型，Fable 5 / Opus 5 都没上榜，
头衔落到了 2026-03 的 Opus 4.7 头上。现在改为 `coding-consensus.ts` 的多榜共识分
（所有第三方编程榜的平均分位，至少 3 榜），`champions.ts` / `persona.ts` / `traits.ts`
三处共用。以后再加「最 X」头衔，先问一句：这张榜覆盖了最新一代吗？

**`params.confidence` 目前没有 `exact`。** 因为 Hugging Face 从中国大陆不可达。
在 GitHub Actions 的境外节点上会正常产出，届时许可证覆盖率也会从 6.6% 往上走。

**角色种族表达不了「这是哪一家」。** LPC 素材库没有鲸鱼、企鹅、麒麟、海螺，
厂商身份由独立的家徽承载，角色种族只负责家族相似性。

## 十、接着做什么

按优先级：

1. **commit + push + 启用定时同步**。这是「零维护」承诺唯一还没验证过的一环，
   也是「新模型出了主页还没有」这类抱怨的根因。Actions 需要 `contents: write`
   与 `issues: write`（失败开 issue）；精灵图不提交进仓库，由部署平台的 `prebuild` 钩子生成。
   首次运行后去 Actions 页确认：sync 成功、快照有 diff、issue 没被误开。
2. **双端部署**：Vercel（海外）+ EdgeOne Pages（国内）。
3. **并排对比模式**。选中 2–3 个模型并排看能力条。当前完全没有；
   排行榜总表已有多选筛选的基础，可以从「勾选后浮出对比条」入手。
4. **`BenchmarkMeta` 补 `name` 与 `higherIsBetter`**。前者能让 `benchmark-registry.ts`
   少维护一份中文名兜底，后者是接入 Brier 类（越低越好）榜单的前提。
5. **编排动画**。精灵图有 4 方向 9 帧行走循环，目前只在悬停时用到。
6. **首页体积**。首页 gzip 约 144 KB，用 SVG `symbol`/`use` 复用重复图形。
7. **英文版**。架子已搭好，是纯增量改动。注意 `coding-leagues.ts`、`benchmark-registry.ts`、
   `persona.ts`、`aptitude.ts`、`champions.ts`、排行榜组件里都有中文硬编码文案，
   做英文版时要一并抽进字典。

## 十一、产品负责人的偏好（历次反馈沉淀，改 UI 前先读）

用户是「程序员鱼皮」，产品判断很明确，下面这些是他明确说过的，别再撞：

**说话方式**
- 全程中文回复。汇报要短，先说结论。
- 不要在页面上放任何解释性文字、口号、废话。已删掉的例子：「每个大模型都是这个世界里的一个人 · 此刻住着 42 位」、
  「怎么看这些屋子」图例、「今日格局」旁的口径说明与「刚发布待评测」名单、页脚「本站不使用 AA 与 LMArena 数据」声明。
  **凡是需要解释的词，换掉它**：西岸都会 → 国外、东方城邦 → 国内、往生堂 → 已退役（后来整页撤掉）、庄园 → 全部模型。

**视觉**
- 「阅读舒服是最重要的」。字号已整体上调过三次，正文 14px 起，别再往小调。像素风来自画与边框，不来自小字。
- 首页两侧要留边距，顶栏要跟正文对齐。用 `.page-shell`（max 1512 + 16/32/48 内边距），
  别再给顶栏单写一套内边距。
- **内页不能比首页素**：每个页面都要有页头（`SiteHeader`：天空带 + 站名 + 导航）。
  只放一个 `SiteNav` 加一片平色底的版本被否过，原话是「背景太素，显得页面很单调」
  「顶部导航栏的布局也很怪」。
- 但**内页的主内容不要套 `SectionFrame`**。补救「素」的时候顺手给时间线、排行榜、
  总表各加了一个外框，同样被否：「不要拿边框把时间线内容主体部分括起来」。
  外框是用来分隔**并列的多个分区**的（首页那四块），内页只有一块内容，画框只是多一道线。
- 想加科技感就加在**框线、角标、小灯、天际线**上（见 `SectionFrame`、HUD 读数、警示灯），
  **永远不要加到正文背后**——网格与扫描线就是这么被撤掉的。
- **正文后面的背景必须是平的。** 石板网格、CRT 扫描线、分区竖条纹全部因「干扰阅读」被撤掉。
  任何规则重复的线条压在文字后面都会被否掉，无论透明度多低。
- 科技感可以有，但只能是点状元素：HUD 小灯、三大块顶边各一条带微光的识别色线。
  每张卡片各自发光被判为「太吵」，撤掉了。
- 配色用低饱和深蓝灰 + 金色强调，第一版紫罗兰调被判为看着累。
- 国外 / 国内**必须分开展示**，默认两边都显示，允许只看一边（Tab）。上下堆叠而不是左右分栏——
  国外 26 家、国内 13 家，左右分栏会让国内那栏下半截空着。
- 「今日格局」的卡片要大到名字不截断。

**数据**
- 榜首必须是真的当下最强。「都 GPT-5.6 / GLM-5.3 了主页还是旧版本」这类问题他一眼就能看出来，
  发现后会怀疑整套排名有问题——门面选拔的代际接班规则就是这么来的。

- 想要零维护自动更新，但建仓一直说「先不急」。目前的替代方案是他说「更新数据」、AI 本地跑。

## 十二、最近一轮改动速览

「我想知道智谱有没有多模态模型」，用当时的站走一遍要五步，而且最直觉的那条路

## 十三、如果你用 subagent 继续开发

本项目是多个并行 Agent 协作产出的，边界划分如下，沿用可以避免冲突：

| 范围 | 归属 |
|---|---|
| `scripts/sync/**`、`data/**` | 数据管线 |
| `scripts/sprites/**`、`assets/**`、`public/sprites/**`、`src/lib/sprite/**` | 美术管线 |
| `src/app/**`、`src/components/**`、`src/lib/`（除 sprite）、`src/data/**` | 前端 |
| `src/lib/types.ts`、`package.json` | **共享，改动前先协调** |

给 Agent 派活时把「不可违背的原则」那一节贴进 prompt——
本项目已经出现过两次 Agent 出于好意做出违背数据诚信的优化，都是靠人工复核挡下来的。

**并行时用 `src/lib/types.ts` 当握手接口。** 实测有效的做法是：
主 Agent 先把契约（新字段、新类型）定下来，然后数据管线与前端各自对着契约并行开工，
前端在契约字段还没落地时走一段兼容回退（例子见 `aptitude.ts` 的 `codingScoresOf`，
`coding[]` 为空时就地从三个历史字段合成等价物）。这样谁先完成都不会让站点白屏。

**派活的 prompt 里一定要写清「不要做什么」。** 收益递减区的数据源、
已经验证过行不通的规则、别人正在改的目录，写清楚比事后返工便宜得多。
